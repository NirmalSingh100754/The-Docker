Docker packages the app and all its required dependencies into one container. This container can be moved to any system and it should run the same way everywhere.
command to see if the docker is running :- docker info
containers :- containers are the way to share our application with its dependencies basically replecating entire local development environment.
properties of container:-
1> Portable
2> Light Weight
Docker Image:- Blueprint helps us create multiple containers.
system resources are used by containers not by the image the relation between image and container is similar to relation between class and its object.
docker run -it ubuntu :- this will run the ubuntu machine on the docker in interactive mode after pulling and downloading from docker hub.
Docker commands:
1. docker pull image_name
2. docker images
3. docker run image_name
4. docker run -it image_name
5. docker stop cont_name/cont_id
6. docker start cont_name/cont_id
7. env :- know all about the environment
8. docker ps -a :- shows all containers available
9. docker ps :- shows only running containers
10. docker rmi image_name :- remove an image from docker
11. docker rm cont_name :- remove or del container from docker
12. docker pull image_name:version by default latest
13. docker run -d image_name :- detach -- we can run containers in background; by default all containers are attached
14. mysql-> docker run -d -e MYSQL_ROOT_PASSWORD=pass mysql :- a root password is required to run the mysql container
15. docker run --name mysql-older image_name :- this will create the container with mysql-older

Docker image Layers
conatiner -> layer 1 -> layer 2 -> base layer(linux, etc.,)
layer 1 -> layer 2 -> base layer(linux, etc.,). => read only layer

Port Binding
-> docker run -p8080:3306 image_name ::->every container has different ports attached from the host system but if we want we can bind the host port with container port to recieve the request recieved at host port in container port.
-p8080:3306 here -p is used to bind ports where 8080 is hosts port while 3306 is containers port.
A same port of host machine cannot be binded to different conatiners ports.

Troublrshoot command
1. docker logs cont_name
2. docker exec -it cont_id /bin/bash or cont_id /bin/sh

Difference btw docker and virtual machine
every machine have 3 layers hardware -> host OS (kernel) -> Apllication Layer 
now the difference btw docker and virtual machine is that docker uses Host OS kernel and only virtualize Apllication Layer that's why docker have less control on machine as well as its lighweight while on the other hand virtual machines vitualize both Host OS kernel as well as application layer.
Virtual machines are compatible with all OS while docker was intially built for only linux systems only.

Docker Compose
.yaml file we can write all commands here in a .yaml file and instead of running the container from terminal we will be runnig it from this file yaml(yet another markup language)

it's basically a toll for defining and running multi-container appliactions.

commands:
docker compose -f fileName.yaml up -d //containers created and run in detach mode
docker compose -f fileName.yaml down //delete all conatiners 

In yaml file we do not write network it by default creats a differentnetwork and run all conatiners in same Network

Dockerfile- Blueprint how to dockerize our application.

Most common Instrucruions of dockerfile 

FROM base_image(node image for tsetapp)
WORKDIR working directory
COPY copy from host to image
RUN used to run instructioms ex: run pip install...
CMD similar to RUN command this instruction sets the default a container using this image will run. for example we use node server.js to run our testapp this same will be the CMD command for our testapp.
EXPOSE used to expose any port of image
ENV we cna define our own environment varibales

Example:-
FROM node
# testapp => node => debian layers of our image
ENV MONGO_DB_USERNAME=admin \
    MONGO_DB_PASSWORD=qwerty
RUN mkdir -p testapp
COPY . /testapp
CMD ["node", "/testapp/server.js"]

command to rub this file :- docker build -t testapp:1.0 .   '-t stands dor tag the image built its tag will be 1.0
